# SÜLD skill tree — architecture

This is the engineering description of the class skill tree (`/skills`). It records what exists in the repository,
which existing systems it reuses, and where each rule lives. The honest status of every subsystem is in
[`audit/skill-tree-status.json`](../audit/skill-tree-status.json) and [`SKILL_TREE_QA.md`](SKILL_TREE_QA.md).

## 1. Forensic audit (before any code)

Searched for `Skill`, `SkillTree`, `Ability`, `PlayerProfile`, HUD, resource pack, EXP/level, combat, listeners, GUI.

| Existing system | What it is | Reused how |
|---|---|---|
| `PlayerProfile` (suld-api) | UUID-keyed character: class, level/EXP, coins, quest state, versioned for optimistic saves | **Extended** with `SkillState` (no second profile) |
| `ProfileRepository` / `JdbcProfileRepository` / `InMemoryProfileRepository` / `SchemaMigrator` | The only storage architecture (MySQL / PostgreSQL / memory), Flyway-style V1…V9 | **Extended**: migration V10 adds `skill_data`; same upsert, same async executor |
| `DefaultProfileService` | Profile cache + save/unload per session | Skill state loads/saves with the profile (join already has it cached) |
| `Spell`, `SkillService`, `ComboTracker`, `ResourcePool` | The 20 class spells (4 per class), click combos, class resource | **Kept as the active-skill base kit**; the tree modifies them (`SpellMods`) |
| `CombatListener` / `CombatCalculator` | ATK/crit/loot/EXP formulas for SÜLD mobs | Tree stats feed `attackOf`, `critOf`, crit multiplier, EXP and loot rolls |
| `ProgressionService` + `LevelUpEvent`/`ClassSelectedEvent` | EXP, levels, domain events on the Bukkit bus | Level/class events re-bind the tree and announce points |
| `QuestService` / `QuestChain`, `StyleService` (discoveries) | Story progress, discovered regions | Skill points are derived from finished chapters and discovered regions |
| `HudService`, `SkillService.actionBar`, `OnboardingService` | Sidebar, action bar, join hints | Points row, ultimate cooldown and hints added to the existing ones |
| `Menu` / `Menus` / `MenuListener`, `gen_ui.py`, `Glyphs` | Chest menus with title-glyph backgrounds, pack generator | `SkillMapMenu` is a `Menu`; assets generated by `gen_ui.py` |
| `ResourcePackService`, `pack_budget.json`, `tools/validation` | Pack delivery + budget/validation | New textures go through the same generator, validator and budget |

Nothing named `SkillManager`, `LevelManager`, `HUDManager` etc. was created; there was no skill tree before.

## 2. Layers

```
suld-api (pure Java, no Bukkit)                       suld-plugin (Paper)
  skill/tree/SkillNode, SkillTree  ── graph + validation   skill/SkillTreeService  ── cache, attributes, procs, keystones
  SkillAllocation  ── ranks, rules (unlock/refund/trim)    skill/SkillService      ── spells; modifiers applied here
  SkillBuild       ── aggregated effects (precomputed)     skill/Ultimates         ── 15 ultimates (F)
  SkillEngine      ── points, unlock, refund, reset, builds skill/OrbOfOblivion     ── respec item
  SkillState       ── persisted document (JSON)            gui/SkillMapMenu        ── the map (pan/zoom/search/filter)
  SkillTreeLoader  ── data-file reader + validator         command/SkillCommands   ── /skills /skill /skillsadmin
  EffectText       ── generated Mongolian tooltips         persistence (V10)       ── skill_data column
  resources/skills/*.json  ── the content
```

Every rule is in the pure layer and unit tested; the plugin layer only supplies context (level, chapters, discovery) and
side effects (attributes, particles, damage).

## 3. Data model

* **Nodes live in data files** (`suld-api/src/main/resources/skills/{baatar,mergen,boo,darkhan,khulegchin,universal}.json`,
  copied to `plugins/SULD/skills/` on first start so admins can edit them). `universal.json` is merged into every class.
* A node has: `id`, `name`, `description`, `category` (CORE / DEFENSE / SPELL / OFFENSE / UTILITY / KEYSTONE / ULTIMATE),
  `icon` (vanilla item), grid position, `cost` per rank, `maxRank`, `level`, `requires` (extra nodes with rank),
  `effects`, `tags`, `keystone`, `capstone`, `hidden`, `secret`, `nodeVersion`.
* Edges (`edges`) are the progression graph; `exclusive` pairs are the red links (two nodes that cannot both be learned).
  A node can be learned when a neighbouring node is learned **and** its extra requirements, level, points and
  exclusivity are satisfied. Convergence = `requires`; branching = edges; optional side branches = dead-end nodes.
* Effects (sealed): `stat`, `mod` (spell modifier), `proc` (passive spell: trigger, chance, kind, cooldown),
  `ultimate`, `keystone`.
* **Persistence is by node id**, never by position: `SkillState` = `{v, ranks:"id=rank;…", active, granted, builds{name:ranks}, respecs[]}` stored as one JSON
  document in `suld_profiles.skill_data` (V10). Unreadable or newer-version data **fails the load** (the player is refused
  rather than loaded with an empty tree that would be saved over their build). Unknown node ids in a stored build
  (content removed later) are dropped on load (`normalise`) and the points are refunded.
* Not implemented as node fields: `requiredQuest`, `requiredAchievement`, `requiredItem`, `requiredResource`
  (there is no achievement system; quest/item/resource gates would need game hooks that do not exist yet).

## 4. Validation (data files)

`SkillTreeLoader` checks JSON syntax, `version`, `class`, required fields, id pattern, ranges (cost, rank, level,
coordinates, chance), enum values (lists the valid ones), spell ownership and modifier support
(`SpellMods.supports`), duplicate ids/coordinates, edges between neighbours only, no crossing diagonals, path vs
exclusive conflict, unknown/self `requires`, keystone/capstone flags, rank limits for proc/keystone nodes,
reachability of every node from the root. Each problem is reported as `file: field.path: message`. A class with any
problem keeps its previous tree (the bundled one at first start); everything is logged at SEVERE and
`/skillsadmin validate` prints it.

## 5. Skill points (the economy)

`SkillPoints.total = forLevel(level) + forChapters(finished) + forDiscovery(regions) + granted`

* `forLevel`: one per level to 30, then one per two levels → 44 at level 60.
* `forChapters`: one per three finished story chapters (5 for the 15-chapter story).
* `forDiscovery`: one per five discovered regions (max 4).
* `granted`: administrator grants (`/skillsadmin grantpoints`).
* All parts are derived from persisted state, so a point cannot be lost or duplicated. Spending is
  `SkillAllocation.spent()`; `available = total − spent`. Whole tree ≈ 80+ points per class, so choices are forced.
* Dungeon/boss/achievement points: **not implemented** (no per-dungeon first-clear record exists to derive them from).

## 6. Effects (what really changes in the game)

| Effect | Where it is applied |
|---|---|
| MAX_HEALTH, MOVEMENT_SPEED, ARMOR, KNOCKBACK_RESISTANCE, BLOCK_BREAK_SPEED | transient attribute modifiers (re-applied on join/respawn/change) |
| ATTACK_PCT, CRIT_CHANCE, CRIT_DAMAGE | `CombatListener.attackOf/critOf` + crit multiplier (melee, arrows, spells) |
| SPELL_DAMAGE, spell `DAMAGE_PCT` | `SkillService.hurt`, volley arrows, passives |
| DAMAGE_REDUCTION, DODGE_PCT, THORNS | `EntityDamageEvent` HIGH / MONITOR |
| LIFESTEAL, HEAL_POWER | hit handler / `SkillTreeService.heal*` through `EntityRegainHealthEvent` |
| RESOURCE_MAX, RESOURCE_REGEN, COST_REDUCTION | `SkillService` pool size, regen, spell cost |
| EXP_PCT, LOOT_PCT | `CombatListener.onDeath` (EXP × multiplier; extra loot-table roll with that chance) |
| COOLDOWN_REDUCTION | passive-spell cooldowns and the ultimate cooldown |
| Spell modifiers (DAMAGE, COST, RADIUS, BURN, SLOW, WEAKEN, VULN, HEAL_ON_HIT, KNOCKUP, SHIELD, HASTE, REFUND, ECHO, PULL) | `SkillService.cast/hurt/riders` |
| Passive spells (triggers HIT, CRIT, KILL, CAST, SPELL_HIT, DAMAGED, LOW_HP, SNEAK; kinds HEAL, SHIELD, SPEED, STRENGTH, RESIST, RESOURCE, AOE, IGNITE, SLOW_AREA, BONUS, SMITE, CHAIN, CLEANSE, SHOVE) | `SkillTreeService.fire`: chance, per-node cooldown, no re-entrancy |
| Keystones | `Мөнх Тэсвэр` (low-HP resistance, half healing), `Нэг Сумны Хувь` (single arrows ↑, volley ↓), `Тэнгэртэй Холбогдох` (resource ↑, max HP −25%), `Алтан Дөш` (durability, spell power/burn), `Талын Салхи` (horse speed, walking −10%) |
| Ultimates (15, one per class path) | F key (`PlayerSwapHandItemsEvent`) while holding the class weapon; 60 resource, 45 s cooldown |

Performance: the `SkillBuild` of a player is computed once per change and cached; no per-tick scanning. Timed work
(shields, ultimates) is one-shot or self-cancelling `BukkitRunnable`s with hit/particle caps; per-player state is removed on quit.

## 7. Respec, builds, admin

* Refund one rank (right click / `/skill <node> refund`) keeps the build connected; refunding the whole tree or a branch
  goes through a confirmation screen, costs coins (`skills.respec.coins-per-point`, free up to level 10), has a cooldown
  (300 s) and is recorded (last 10 respecs). An **Orb of Oblivion** (1 diamond + 4 ender pearls, or admin) refunds for free
  with no cooldown. Level, EXP, coins and saved builds are never touched.
* Builds: `/skills build save|load|delete|list <name>`, slots from config. Loading validates node existence, path,
  requirements, rivals, level and points; a build that no longer fits is refused whole.
* Admin: `/skillsadmin inspect|grantpoints|unlock|reset|orb|fire|reload|validate` (permission `suld.admin.skills`).

## 8. Interactive map

Chest-based, server controlled (no client mod). Background and connector lines are pack assets generated by
`tools/pack/gen_ui.py`. Two zoom levels (detailed 5×3 nodes with connectors; overview 9×5 nodes), pan, category filter,
chat search with highlight, node states (locked, available, learned, maxed, needs points, level locked, prerequisite
missing, excluded, keystone, ultimate, hidden, secret), tooltips generated from the data. See `SKILL_TREE_DESIGN.md`.
